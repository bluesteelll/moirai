# Spec sync 2b

Changes to `docs/spec/` made after the wave 2b work packages (WP-20, WP-21, WP-22, WP-30b/31b/33b, WP-32, WP-40, WP-90a,
WP-90b, WP-91, WP-93a, WP-95), their reviews and closures, and the WP-95 arbiter rulings, together with WP-92's edits
of `rules/link-merge-rules.md`, `rules/status-machines.md`, `rules/role-write-policy.md` and `rules/policy-keys.md`,
made in the same working tree (S2B-M-27, S2B-M-29 to S2B-M-31). Each author role appends its own section.
Each row gives:

- **id**: `S2B-<role letter>-<n>`, the letter being P (R-SPEC-P), R (R-SPEC-R), F (R-SPEC-F) or M (R-MODEL);
- **file §**: the file and the sections changed;
- **change**: what the text now says, and for a contested routing row the decision and its reason;
- **sources**: the routing row of the sync-2b routing table (RP-, RR-, RF-, RM-n) and the findings it closes, in that
  table's ids (S = a work package's "Spec findings" section, R = a review or closure finding, A = an arbiter ruling,
  F = a spec role's follow-up note; the index at the end names the work package of each);
- **affects**: the code or fixtures that must follow the change, by crate (`moirai-model`, `moirai-format-oracle`,
  `moirai-toylog`, `moirai-vfs`, `moirai-vfs-sim`, `moirai-os`, `moirai-files`, `moirai-diff`, `moirai-tokcount`) or
  fixture directory (`fixtures/<dir>`), or "none". Spec follow-ups by another role are named after a semicolon.

Owner questions raised by this sync (OWNER O-1 to O-10 of the routing table) are not decided here; rows that depend on
one say so. They are raised in `owner-questions.md` as OQ-A-1 to OQ-A-4 ("Owner questions" below maps them), and the
design-text edits that follow the sync are listed under "WP-81a".
