## 1. How to read this file

- **One row per item.** Every row of the tables of [60 §2.5] has at least one row here. A [60 §2.5] row with enumerated or
  separable parts (the fault-model items (1)–(12), the protocol decisions, the audit rows that list several structures) is
  split into one row per part, so that a fixture and a model function can be named per part. The R4 and R5 reservation
  tables of [60 §2.5] carry the same items as [40 §2.11] and [50 §8.1], which are authoritative ([60 §2.5], [F01 §2.4]);
  each R-n and Fn therefore has one row that serves both. The "Cross-platform" and "Harness-agnostic interface" audit rows
  are summary rows; their parts are the X-F rows (§10) and the [90 §10.1] rows (§11).
- **Columns** ([F01 §2.7]). `item` is a stable row id (`60-…` for [60 §2.5], `R-n`, `Fn`, `X-Fn`, `90-…` for
  [90 §10.1]); `frozen content` states what the item freezes; `chapter §` lists every section that specifies a part of it,
  each followed by the part; `fixture` and `model function` are blank until R-FIX and R-MODEL fill them.
- **Fixture column.** Backticked paths, relative to the repository root or to `fixtures/`, `*` allowed. `xtask coverage`
  checks that each exists. Spec sync 2b copied into it, for every row, the existing paths of that row's entry in
  `fixtures/hex/INDEX.md` §5, which R-FIX keeps in this file's order and path convention (R-FIX may not write
  `docs/spec/`); a cell that ends with `` (`hex/INDEX.md` §5) `` defers to that entry for the fixtures it names in words
  (every `HEAD`, every record of a store, "not a byte structure") and for the families outside `hex/`. R-FIX's later
  additions are copied the same way at each spec sync.
- **Model-function column.** Backticked paths such as `moirai_model::idem::lookup`. `xtask coverage` checks that each is a
  `fn` in `crates/moirai-model/src/` whose comment block carries a `spec:` tag that cites one of the row's `[… §…]`
  citations exactly as written in the `chapter §` cell, or the row's item id. Spec sync 2b filled it from the model as it
  stands: up to four functions per row whose `spec:` tag cites one of the row's citations or its item id, written without
  the `moirai_model::` prefix and resolved as `xtask coverage` resolves them. The rule files' own Coverage cells follow
  the same names ([RULES/README]; R-MODEL's RM-20).
- **UNMAPPED.** A row whose item no chapter specifies has **UNMAPPED** in its `chapter §` cell. [PLAN §7] E1 requires none
  at the freeze.
- **CONFLICTING** (pass 1, A1-61). A row whose cited sections contradict each other is not counted as mapped: its cell ends
  with **CONFLICTING**, the findings that resolve it and the role that owes the fix. The row counts as mapped again when those
  findings close. [PLAN §7] E1 requires none at the freeze, as for UNMAPPED.
- **Verification.** Every citation below was opened on 2026-09-28: the section exists in the chapter as written and states
  the part named after it. Rule files are cited by their row ids; they specify semantics, never bytes ([RULES/README]).
